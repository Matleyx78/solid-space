**Stato:** preparazione della chiusura; prova manuale da completare.

## Contenuto

- Scopo, architettura, regole di collaborazione e ADR 0001–0006 accettati (P1).
- Cinque librerie statiche con alias `solid_space::<componente>`, dipendenze in un
  verso solo, preset `debug`, `release`, `asan`, `tidy`, avvisi come errori nei
  preset e banco di prova GoogleTest (P2, PR #9).
- CI per formato, Linux/GCC e clang-tidy, Windows/MSVC, macOS/Apple Clang,
  ASan/UBSan e separazione tra riferimenti e lavoro; comando locale
  `scripts/controlla.sh` (P3, PR #10).
- Formato JSON dei casi con provenienza e valori esatti o tolleranze, validatore,
  24 test del validatore e caso `kernel/cubo-lato-1.json` calcolato a mano (P4,
  PR #11). Nessun dato esterno: `sorgenti.json` contiene una mappa vuota.
- Script REST `ci-attendi.sh`, `ci-errori.sh`, `ci-annota.sh` per attesa della CI
  e lettura degli errori, anche senza token per il repository pubblico (P5, PR #12).

Tutti i pacchetti sono uniti e le issue #4–#7 del milestone `v0.1` sono chiuse.
Non sono inclusi algoritmi geometrici, esecuzione dei casi contro il kernel,
compilazione di OCCT o libslvs, né integrazione in Tecnigrafo. La tappa 0.2
resta in programma e richiede un'apertura separata del responsabile.

## Prova manuale del responsabile

Compilare la tabella prima del merge della PR di chiusura. Partire su ciascun
sistema da un clone pulito del ramo di chiusura, senza `--recurse-submodules` e
senza eseguire `git submodule update`: `third_party/occt` deve restare vuoto.
Servono gli strumenti di [AMBIENTE-SVILUPPO](../AMBIENTE-SVILUPPO.md).
Su Windows usare compilatore MSVC nativo (non WSL), con il suo ambiente attivo;
per gli script Bash usare Git Bash nello stesso ambiente.

Per la prova release sui due sistemi:

```sh
cmake --preset release
cmake --build --preset release
ctest --preset release
```

Controllare assenza di avvisi e successo del banco e del corpus. Prima della
prova senza nucleo, compilare separatamente i target `solid_space_robust`,
`solid_space_naming`, `solid_space_solver`, `solid_space_kernel` e
`solid_space_features` con `cmake --build --preset release --target <nome>`.

Per la prova senza nucleo, dalla stessa radice e sempre senza sottomoduli:

```sh
cmake --preset release -DSOLID_SPACE_BUILD_KERNEL=OFF
cmake --build --preset release
ctest --preset release
```

Il banco deve confermare l'assenza dei target `kernel` e `features`; OCCT non
deve essere cercato. Per provare poi il comando locale su Linux e Windows,
ripristinare prima l'opzione e usare Bash:

```sh
cmake --preset release -DSOLID_SPACE_BUILD_KERNEL=ON
scripts/controlla.sh --tidy
```

Confrontare i passi con quelli della CI: formato, configurazione, compilazione,
test e clang-tidy. Annotare versioni degli strumenti, commit effettivamente
provato ed eventuali anomalie; non sostituire l'esito manuale con quello della CI.
